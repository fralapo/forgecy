# @forgecy/carousel

Carousel renderer, templates and export (M3).

- **Formats** (`FORMATS`): Instagram 4:5 and LinkedIn document in the MVP; Instagram 1:1, Stories 9:16, Facebook 4:5 and TikTok photo ready for v1, with real pixel sizes and default safe zones. For reports (`kind: "report"`, no channel) there are `report_a4` (1240×1754 at 150 dpi, PDF in true A4) and `report_16x9` (1920×1080); `pdfPageSize()` gives the page in points. Report page roles: `section`, `finding`, `problem`, `next_steps`, `method`.
- **`template.json`** (`templateManifestSchema`): format, number of slides, layouts with role and position, slots (`text`, `list`, `image`) with limits, bundled fonts, CSS variables bound to the Brand Identity's color and font roles, type scale, composition rules. The JSON schema for the editor is `templates/template.schema.json` (`pnpm --filter @forgecy/carousel schema`).
- **Slides**: JSON with `layout` and one value per slot. `buildSlideSchema(template)` and `buildCarouselSchema(template)` produce the Zod schemas used to validate slides written by the AI or the editor (character limits, items, first and last slide, CTA, images per slide). `==word==` highlights a word in slots with `highlight`.
- **`renderSlideHtml`** (the `SlideRenderer`): fills the layout's HTML inserting values as text, applies the brand's colors and fonts as CSS variables, strips scripts, handlers and external references from the template and returns a self-contained document of exactly `width×height` px. It is pure and synchronous: same input, same string.
- **Validation** (`validateTemplatePackage`): the Template editor checklist, with file and line for every problem (`TEMPLATE-INVALID`, `ASSET-MISSING`): template.json, files present, slots consistent between HTML and metadata, bundled fonts, hand-written colors, font sizes outside the scale, variables not bound to a role, disallowed markup, valid examples.
- **Export** (`@forgecy/carousel/export`, worker only): Chromium via `playwright-core`, one PNG per slide at the exact resolution, PDF with one page per slide (the same PNGs), ZIP with PNG, PDF, `caption.txt`, `texts.md` and `slides.json`. Names `{client}_{content}_v{n}_{format}_{nn}.png`; fixed dates and sorted entries, so the same version gives the same bytes. Before approval, a “Draft” watermark and the `_draft` suffix. After rendering it measures every slot: clipped text, outside the slide or the safe zone, overlapping, too many lines, low-resolution images.
- **Jobs**: `carousel.export` (`export` queue) and `carousel.validate_template`; the handlers are in `carouselWorkerHandlers()`.
- **Catalog** (`@forgecy/carousel/catalog`): `templates` table, one row per version with the package as a ZIP in storage (hash verified on every read). Import creates or replaces a draft and enqueues `carousel.validate_template`, which adds the test render; it can be sent to review or published only with validation passed and version notes. States: draft, in review, published, archived. Export and editor read the latest published version, or the one pinned by the carousel even if archived. Only users with `templates.manage` change the catalog; agents never do.
- **Node** (`@forgecy/carousel/node`): reads packages from a folder or a ZIP (max 50 MB), scans `templates` for import (`FORGECY_TEMPLATES_DIR` for another folder), resolves assets from storage restricted to the client.

Commands:

- `pnpm --filter @forgecy/carousel preview ../../templates/editorial-ig-4x5 /tmp/out`: validates a template, runs the test render and saves the PNGs of every layout with sample and long texts.
- `pnpm test`: the Chromium tests run with `FORGECY_RENDER_TESTS=1` (CI sets it and installs the browser) or with `FORGECY_CHROMIUM_PATH` pointing to a local Chromium.
