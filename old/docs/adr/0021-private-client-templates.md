# 0021 · A client's template is private to that client

- Status: accepted
- Date: 2026-10-09
- Completes: 0015 (section "A template is only served to its own client")

## Context

A template row has `client_id`: null is an agency template, shared by every client; a value makes it the template of that one client. Today only the client import creates client-owned templates (`docs/adr/0015-client-import-trust-reset.md`: every imported template is a Draft owned by the client). Carousels, Brand Books and automations name a template by key and, when pinned, version (`contents.template_key`/`template_version`, `content_versions.meta.templateVersion`, `brand_book_exports.template_key`/`template_version`, `automations.params.templateKey`). A key alone, or a key and version written in a row, must never reach a template that belongs to another client.

ADR 0015 scoped the main lookups (`dbTemplateSource` takes the client, `getTemplate` and `listUsableTemplates` filter, the Brand Book pins `newestVisibleVersion`) and left the item open in `docs/SECURITY_CHECKLIST.md` section 7. The inventory for this decision read every place that looks a template up by key, version or id, or lists templates:

## Decision

1. **Resolution.** A template is resolved and used only where `client_id is null or client_id = <the client of the content, export or Brand Book>`. Every lookup above that serves a deliverable already takes that client; this decision makes it the rule. Without a version, the newest published version the client may use wins (its own or the agency's, whichever is newer); with a version, that exact row if the client may use it.
2. **Another client's template is missing, not forbidden.** A row that names another client's private template fails with the existing localized "unavailable/not found" errors (`content.errors.templateUnavailable`, `jobs.errors.templateIdNotFound` / `templateVersionNotFound`, `brand.book.jobErrors.templateMissing`); it is never rendered. A distinct message ("belongs to another client") would tell a person that the key exists for someone else, so none is added. Automations, which already fall back to the first usable template when the configured one is unavailable, fall back the same way.
3. **Key and version stay unique across the installation.** `templates_key_version_idx` is `(key, version)`, not per client, and stays: changing it would need a migration and would make every lookup by key and version ambiguous between two clients, which is the bug class this decision closes. Two clients can each have a private template with the same key, in different versions; each resolves its own (or the agency one, if newer). A collision on import is handled as ADR 0015 says: the package's version becomes `<base>-import.<n>`. The client import never reuses, replaces or attaches to another client's private template, including when the person chooses "use existing" (`templateReuse` only offers agency templates and, for a replacement, the replaced client's own; Verify lists no conflict when only another client holds the key).
4. **The Templates screen never overwrites a private draft.** Uploading a package whose key and version a client-owned row holds is refused (`templates.errors.versionPrivate`, en and it) instead of replacing that client's package while the row stays private to it.
5. **A deleted client's private templates go with it.** `deleteProspect` deletes the prospect's templates in the same transaction (the foreign key's `set null` would turn them into agency templates). The client import's replacement deletes and recreates the client inside one transaction and reassigns its templates there, so nothing is exposed in between.
6. **One template's versions are one owner's.** The template detail page lists the versions with the same key and the same `client_id` only.

## Consequences

- Tests: `packages/carousel/test/catalog.integration.test.ts` (clients A, B, C with a shared key: each served its own, the agency one to C and to no client, a pinned version of the other client's template refused by `dbTemplateSource` and by the export job before any rendering, the agency upload refused); `packages/content/test/template-scope.integration.test.ts` (`getTemplate`, `listUsableTemplates`, `createCarousel` refused); `packages/brand-book/test/template-scope.integration.test.ts` (pins its own version, render refused for another client's); `packages/client-transfer/test/import.test.ts` ("never reuses or changes another client's private template, even when asked to reuse"); `packages/audit/test/service.integration.test.ts` (prospect deletion takes its template). Unit: `template-scope.test.ts`, `book-template.test.ts`, `client-transfer/test/templates.test.ts`.
- `docs/SECURITY_CHECKLIST.md` section 5 has the drill; section 7's item is closed.
- An agency person who wants a client's private template for everyone imports it again from the Templates screen under a new version (an agency template); there is no "make shared" action.

## Not covered

- **Who may see the installation catalog.** The Templates screen, its detail page, `/render/templates/[id]/[layout]` (sample data, neutral brand), the template validate job and the global search list or open every template row, private ones included, to anyone allowed there (`view` or `templates.manage`). This is managing templates, not using them for a deliverable. Whether a person not assigned to client A may see A's private templates there is per-client access control (ADR 0020), which adds `assertCan(..., row.clientId)` and the search scope.
- **`/render/slide` trusts the `clientId` of the request** for which private templates it may serve; `assertCan(user.actor, "view", body.clientId)` is the access check (ADR 0020).
- **Other future client deletions.** The foreign key is still `on delete set null` (no migration in this change). A new path that deletes a client must delete its private templates first, as `deleteProspect` and the import replacement do; switching the key to `cascade` is the follow-up if a third path appears.
- Assigning an agency template to a client, or a client's template to the agency, from the interface: not offered; only the client import creates private templates.
- No catalog badge says which client owns a private template.
