# Languages and translations

Forgecy shows every piece of interface text from message files, never from the code. English is the source language and the fallback; Italian is a translation. Today the supported languages are **English (`en`)** and **Italian (`it`)**.

Two languages are kept apart:

- **Interface language**: what a person sees in Forgecy. It is a personal preference (Settings → Preferences); when unset, Forgecy follows the browser's language and falls back to English.
- **Deliverable language**: the language of what goes to a client (reports, carousels, captions). It is chosen per audit or per content, exactly as before, and does not depend on who is signed in.

## Where the text lives

```
packages/i18n/
  messages/
    en/              ← source of truth, one JSON file per area (namespace)
      common.json    ← shared words: actions (Save, Cancel...), roles
      enums.json     ← labels of shared enums (AI policy, client status, job status)
      validation.json← form validation messages
      errors.json    ← generic messages per error code and errors shared by every module
      shell.json, home.json, auth.json, clients.json, settings.json, mail.json, ...
      index.ts       ← one import per file
    it/              ← same files, same keys, Italian values
  src/               ← locales, loading with English fallback, formatting, translator for the worker
```

Each JSON file is a namespace: `settings.json` holds the keys used as `t("settings.preferences.title")`. Keys are English, nested by page or component, and describe the role of the text, not its words (`preferences.saved`, not `languageUpdatedDot`).

## Writing interface text

Messages use the ICU format: variables in braces, plurals and selections spelled out in the message, never assembled in code.

```json
{
  "greeting": "Hi {name}",
  "slides": "{count, plural, one {# slide} other {# slides}}",
  "status": "{status, select, draft {Draft} approved {Approved} other {Unknown}}"
}
```

- **Server components and actions**: `const t = await getTranslations("settings")`, then `t("preferences.title")`.
- **Client components**: `const t = useTranslations("settings")`.
- **Metadata**: `generateMetadata` with `getTranslations`, never a static `metadata.title`.
- **Rich text**: tags in the message (`"Read the <link>terms</link>"`) rendered with `t.rich("key", { link: (chunks) => <a ...>{chunks}</a> })`.
- **Enum labels**: a map from value to key, never from value to text: `te(\`aiPolicy.${policy}\`)`.
- **Dates and numbers**: `await getFormat()` on the server, `useFormat()` in client components (`format.date(value)`, `format.number(n)`, `format.relative(value)`). Never `toLocaleString("en-GB")` or a fixed `Intl` locale. English uses British conventions (6 Oct 2026).
- **Validation**: Zod messages are full keys, `vmsg("validation.nameRequired")` or a key of the module's own namespace, and the action returns `await firstIssue(parsed.error)`.
- **Domain errors**: packages throw `localizedError("not_found", "products.errors.notFound", { name })` (from `@forgecy/i18n`); the key lives in the module's namespace, under `errors`. Actions show them with `await errorMessage(err)`. The English text stays in `err.message` for logs and the API.
- **Job errors**: a handler throws `new NeedsAttentionError(englishMessage(key), details, messageRef(key))` or a `localizedError`; the worker stores the reference in `jobs.error_ref` next to the English `jobs.error`, and pages show it with `refText()` (server) or `useRefText()` (client).
- **Outside React** (worker, emails): `const t = await getTranslator(locale, "mail")`.

Text that is not language does not need a key: product and brand names (Forgecy, OpenAI), user data, and symbols such as `—` or `·`.

## Checks

- **Types**: keys are typed from the English files, so `t("settings.nope")` does not compile.
- **Lint**: `forgecy/no-hardcoded-text` (in `scripts/eslint/`) rejects words written in JSX and in text props (`title`, `label`, `placeholder`, `aria-label`...).
- **Tests** (`pnpm --filter @forgecy/i18n test`): every language has exactly the English keys, every message is valid ICU with the same variables as English, plurals have an `other` case, and every language folder matches the list of supported languages.

At runtime a key missing from a translation shows the English text instead of failing.

## Changing a text

Change the value in `messages/en/<namespace>.json` and the same key in every other language. Renaming or removing a key means changing it in every language; the tests list whatever was forgotten.

## Adding a language

1. Copy `packages/i18n/messages/en/` to `packages/i18n/messages/<code>/` (for example `fr`) and translate the values, not the keys. Set `meta.languageName` to the language's own name (`Français`).
2. Add the code to `LOCALES` in `packages/core/src/locale.ts`, its loader in `packages/i18n/src/messages.ts` and its date and number region in `packages/i18n/src/locales.ts`. TypeScript points to each place.
3. Run `pnpm --filter @forgecy/i18n test`. The language then appears in Settings → Preferences.

## Client deliverables

Deliverables use the same files and the same format, but in the deliverable's language (the content's `language`, the audit's `reportLanguage`), whoever renders them:

- **Texts written by code** (report cover kicker, priorities, “Draft” watermark...) live in the `deliverable` namespace and are read with `getTranslator(language, "deliverable")`.
- **Labels printed by a template** (“Swipe”, “Prepared by”...) belong to the template: layouts mark them with `data-fc-text="key"` and each template ships `locales/en.json`, `locales/it.json` (see `templates/README.md`). The renderer takes `language` and falls back to English. A template imported without a language file prints its English labels.
- Dates in deliverables are formatted with `createFormat(language)`.

## Not translated

Data typed by people or produced by the AI (client names, briefs, findings) stays in the language it was written in. Values stored in the database are machine values (`draft`, `approved`) and are translated only when shown.
