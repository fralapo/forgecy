# 0015 · A client package is untrusted input: nothing arrives approved

- Status: accepted
- Date: 2026-10-08
- Amends: 0009 (import behaviour)

## Context

ADR 0009 imports a package by generating new ids and keeping every other value. The package is written by whoever made it: statuses and "who approved" are as free to choose as ids and storage keys. The audit found that a crafted package could arrive with content already Approved or Exported, with approvals attributed to real local people (people are matched by email, which the package states), with published templates (including `origin: system`), with the AI consent of the client already given, with automations active and with Brand Identity versions already published. Each of these skips a gate that `can()` enforces for everything created here.

The structural checks (every foreign key and `client_id` stays inside the package, storage keys are this client's, files match their checksum) keep a package from reaching into another client. They do not say what a row may claim, which is this decision.

## Decision

The importer applies `applyImportTrust` (`packages/client-transfer/src/trust.ts`) to every row, after the final scope check and before the insert, on the remapped parsed rows. The rules are per table:

| Table                                                                                                               | On import                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `clients`                                                                                                           | new client: `ai_policy` is the stricter of the package's and the installation's default for new clients (order `no_ai` < `local_only` < `external_restricted` < `external_allowed`), `approved_providers = []`, `sendable_assets` = all kinds (the schema default); replacement: all three keep the replaced client's current values |
| `contents`                                                                                                          | `in_review`, `changes_requested`, `approved`, `exported` become `draft`; approved version, outline approval, reviewer, review note, submitter and lock cleared                                                                                                                                                                       |
| `content_approvals`, `content_exports`, `audit_report_exports`, `brand_check_issue_states`                          | not imported (approval records, export records, waivers granted elsewhere); package files that only these rows pointed at are not copied                                                                                                                                                                                             |
| `assets`                                                                                                            | an AI image that was `approved` becomes `draft`; who decided, and the rights attestation of an upload (`rights`) are cleared; an AI image's `commercialUse: verified` goes back to `pending_verification`                                                                                                                            |
| `templates`                                                                                                         | always `draft`, `origin = agency`, owned by the client; submission and publication fields and `validation` cleared                                                                                                                                                                                                                   |
| `automations`                                                                                                       | `active` becomes `paused`                                                                                                                                                                                                                                                                                                            |
| `automation_runs`, `automation_run_items`                                                                           | a run or item that was running or queued becomes `cancelled` (nothing here would ever finish it)                                                                                                                                                                                                                                     |
| `audits`                                                                                                            | `reviewed` becomes `in_review`; `delivered` becomes `archived`; reviewer, delivery date and competitors confirmation cleared                                                                                                                                                                                                         |
| `audit_reports`                                                                                                     | `in_review`, `approved`, `exported` become `draft`; submission, review, approval, export and change-request fields cleared                                                                                                                                                                                                           |
| `brand_identity_versions`                                                                                           | `approved` and `published` become `archived` (they can be restored as a new draft); `in_review` becomes `draft`; submission, approval and publication fields, `editor_ids` and `acknowledged_checks` cleared                                                                                                                         |
| `brand_identity_proposals`, `content_creative_directions`                                                           | accepted or rejected become stale (creative directions: accepted becomes proposed); the reviewer or decider is cleared                                                                                                                                                                                                               |
| `brand_book_exports`                                                                                                | `approved`, `exported` become `draft`; approval cleared                                                                                                                                                                                                                                                                              |
| `memory_items`                                                                                                      | `approved` becomes `candidate`; decision and its note cleared                                                                                                                                                                                                                                                                        |
| `content_plans`, `audit_competitors`, `content_comments`, `product_import_files`                                    | acceptance, confirmation, resolution and mapping confirmation (who and when) cleared                                                                                                                                                                                                                                                 |
| strategy and catalogue tables (`content_pillars`, `content_rubrics`, `content_plan_items`, `product_*`, `products`) | status kept (it is the agency's working data and releases nothing); who decided or approved, and decision notes, cleared; per-field conflict decisions of product imports reset                                                                                                                                                      |
| collection pipelines and analysis tables                                                                            | unchanged, with the reason written next to the rule                                                                                                                                                                                                                                                                                  |

Template reuse during import looks only at agency templates (`client_id is null`) and, for a replacement, the replaced client's own templates; another client's private template is never mapped in. Verify uses the same rule (`templates.ts`). Templates are unique by key and version across the installation, so a package template whose version is held by a template that cannot be reused is imported under `<version>-import-<n>` and the rows that name it follow; copying a client inside one installation, or importing a package twice, therefore works.

### Rules fail closed

`checkTrustCoverage` checks the rules against the Drizzle schema. It runs in a unit test and before every import (not when the module loads, so a schema change cannot take export or verify down). It finds the gate columns by name (status, decision, approved/published/exported, accepted, confirmed, acknowledged, resolved, rights, shares and tokens, public, enabled, locks, waivers, reviewers, submitters, deciders) and by value (any enum that has one of `approved`, `published`, `accepted`, `exported`, `active`, `confirmed`, `verified`, whatever the column is called). Then: every client table with such a column, or an export/approval table, needs a rule; every value of a status enum needs a target that is a value of the enum; every gate column has to be named by the rule (cleared, set, or listed as deliberately left); a rule may only clear nullable columns; a rule that changes nothing states why. A new table, a new status value or a new approval column therefore stops the importer until someone decides what it means, as `SOFT_REFS` does for references. A status value this version does not know is refused at import (`UnsafePackageError`).

### A status change must not break a unique index

Mapping statuses changes which rows fall inside a partial unique index, and the package is only known to satisfy the index as it was. The first version mapped `delivered` audits to `in_review`; a client with a delivered audit and a reviewed one then had two active audits (`audits_one_active_uq`) and the import failed. Rule: a mapping may move a row out of such an index, never into it. `STATUS_UNIQUE_INDEXES` lists the status-dependent unique indexes of the client tables (`audits_one_active_uq`, `brand_versions_one_published_uq`, `brand_versions_one_open_uq`, `content_plans_active_uq`); a test checks every mapping against them and fails for any partial unique index of the schema that is in neither that list nor `NOT_STATUS_DEPENDENT`. Check constraints that tie a status to an approver (`brand_proposals_reviewed_by_person`, `content_creative_directions_decided_by_person`, `brand_versions_*_by_person`) are why proposals and directions leave `accepted`/`rejected` and why an approved version leaves `approved` before its approver is cleared.

No package signature: a hash or HMAC proves origin only between installations that share a secret. The checks make an untrusted package harmless instead. A signature can be added later without changing the format (a new manifest field).

## Consequences

A package from a trusted source arrives needing the same clicks it needed on the source (submit, approve, publish, re-enable automations, re-approve the AI providers and rights), and its templates must be published again. A delivered audit arrives archived. This is intended.

A new client from a package never gets more AI freedom than a client created by hand: the installation's default policy caps it, and no provider is approved. The import wizard says so (`clientTransfer.confirm.states`).

Export records are not imported and their files are not copied. Product `truth` levels inside the products' JSON metadata and the `verdict` of brand examples travel as they are; they guide wording and never release anything.
