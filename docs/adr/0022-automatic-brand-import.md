# 0022 · Automatic brand import

- Status: accepted
- Date: 2026-10-09
- Refines: the "AI agents propose and do not approve" rule of `CLAUDE.md` (an import run acts on behalf of the person who started it)

## Context

The Brand Identity import (links and files, then the Brand Analyst, then proposals) ended in a manual queue: accept each proposal, submit for review, approve with a changelog and a self-approval note. Agencies asked for the opposite: paste the links and get an approved brand, taking the website's images too, and later social profiles. A real run on a staging site also showed that the extraction was weak (colors invented from product-variant words, no fonts, no logo, quotes never checked against the page), so removing the human click without fixing the extraction would publish wrong data.

## Decision

- **The person who adds the links is the approver of record.** An import run is started by a person (the "Add a brand" box, a website or profile link added on the Sources page, which is read at once, "Re-analyze", "Scan again" or "Read again", or a client created with a website). The job carries that person as `requestedBy`; accepting and publishing use them as `reviewed_by` and `approved_by`, so the database constraints and the activity log stay true. Nothing takes an actor from the caller and an agent cannot run it as itself: `applyImport` (`packages/brand/src/auto-import.ts`) reads the person from the job, loads their access (`userActor`) and needs, on that client, the same permissions the buttons need (`review`, `edit_draft`, `publish`, `brand_identity.approve`). A run nobody started, a deactivated person, a person without access to the client or without those permissions writes nothing: the proposals stay pending and the source says why.
- **Only public pages apply themselves.** Automatic apply covers `website` sources and the social-profile kinds (`instagram`, `facebook`, `linkedin`, `tiktok`). Documents (brand books, PDFs, screenshots, questionnaires, interviews) keep the review queue, as do manual proposals and proposals from other agents.
- **The gate is verification, not judgment.** An item reaches the draft only if it passes deterministic checks (`packages/brand/src/import/gate.ts`, `verify.ts`): its quote is in the normalized text of the cited page; a hex color is in the data the browser extracted from the site (CSS variables, `theme-color`, computed colors); the proposal still applies to the draft and passes `checksFor`; colors of framework-default palettes (Bootstrap and similar) and generic or system font stacks are discarded. What fails is discarded and counted on the source, not queued, and the activity log gets one `brand.import.gate` entry per source with the counts by reason (no page text). The model may name and give a role to extracted colors, never introduce one. The palette proposed from the site (`knownColors`) is ranked: `theme-color`, variables named for a role (primary, secondary, accent...) including the page builder's kit on `<body>`, button colors by weight, the builder's other globals, the rest; at most six, chromatic first, with at most two neutrals (one light, one dark), so a gray ramp never fills it.
- **A person's work is never overwritten.** A value is kept when a person wrote it (an item with no sources), when it is confirmed (confidence high), when it rests on a source an import does not read by itself (a brand book, a document, an interview, a removed source), or when a person accepted it from the review queue (`brand.proposal.accept`); the proposal is marked rejected with "hand-edited field kept" and counted. Logo variants have no provenance, so they count as written by a person and a re-import does not replace them. Only empty fields, list additions, starting values (the default font tokens) and values that an earlier import applied by itself can change.
- **A re-run adds nothing twice.** A run keeps one value per single-value field (the request with the home and about pages wins) and never contests itself across its sources. An item is not proposed again when the client already has it or waits for it in the same words (case, accents and punctuation aside), or when it rests on the quote an existing item of that field was proposed from. A re-run only tops the site's pictures up to the limit (twelve per client).
- **What needs a person stays pending.** Sensitive fields in conflict or with low confidence, and fields that another source or person also proposes (a brand book, a colleague, another run), wait in the queue.
- **Shared drafts are not published.** If the open draft was created or edited by someone else, or is in review, the accepted items stay in the draft and nothing is published; the source says so.
- **Undo.** The brand page shows "Imported automatically on ..." with the number of items and of items kept for review, and "Undo import": the version the import published goes back to the one before it, restored as a new draft and published by the person who clicks (`undoImport`). It works only on the current version, only when an automatic import published it, and replaces an open draft only after the person confirms.
- **Social profiles: logged-out public pages only.** A profile URL is fetched only when its host is on the platform allow-list (one host set per platform, not whatever the link says), `robots.txt` allows it, with a single request and no login, scripts or follow-up crawling. A link found on an attacker's site that points off-platform is never fetched. LinkedIn `/in/` links found on a site are never followed; a person's LinkedIn profile added by hand imports its text but never its picture. Pages behind a login wall or blocked by `robots.txt` import nothing and the source says so.
- **Images.** Pictures found on the website (and one profile picture per social profile) are downloaded pinned to a public address, capped, sniffed from their bytes and measured after decoding, then stored in the asset library with source `site` and tags `[class, "site"]` (class: product, scene, graphic, logo; "logo" only for a picture in the header or declared as the site's logo, icon or share image on its own domain, so a parent company's or partner's logo is a graphic) or `["social"]`. The logo is also registered as a brand source for the logo variant. Rights stay a person's: images found by a run started by a person who may upload to that client right now (active, with access, `assets.upload`) are attested on their behalf as the site's own content, anyone else's stay drafts; profile pictures stay drafts until someone confirms the rights in the content library, which now accepts `site` images like uploads. The brand page lists them read-only (`listBrandImages`).
- **Prospects with a website publish on creation.** A client created with a website address queues the first scan as its creator, so the import applies itself and publishes the first version without a click. Clients are created in two places: `createClientFor` (the Clients form and "Add a brand") and the Prospect audit actions (`createProspectAction`; `updateProspectAction` also queues a scan when the website changes). What starts a run, always as the signed-in person: those three, "Re-analyze" and the scan banner on the brand page, "Scan again", "Read again", and a website or profile link added on the Sources page.
- **Completeness.** The brand page shows how many of nine sections (about, tagline, audience, tone, aesthetics, fonts, palette, logo, images) are filled (`brandCompleteness`). A section counts only when it has content and passes the publish checks that judge it (`checks.ts`): a one-liner over the word limit fills neither about nor tagline, tone needs every tone axis and four "we are / we are not" rows, logo needs the primary variant, palette three colors of the brand's own; an unverified font license is informational and does not empty fonts. "Next action" counts the same open points as the block cards, so the page never says "no pending actions" while a block lists something missing.
- **Import in progress.** While a website or profile source is queued or being read, the brand page shows an "Import in progress" banner and refreshes itself; on a client with no published version yet, the "no published version" warning, "Start the draft" and the next-action nudge are hidden until the import ends (a failed import shows the normal state and the reason). The website source stays `extracting` until its profiles were read and the automatic apply has run (`runSourceImport` with `holdStatus`); only then the crawl writes its final status and status line, also when a step failed.
- **Names guessed from the address.** "Add a brand" with a link names the client after the host ("Staging g" for `www.staging-g.deodue.it`, `nameFromUrl`). After the crawl, while the name is still exactly that guess and nobody saved the client's details (`prospect.update`) or renamed it, the client takes the name the site gives itself (`siteBrandName`: the JSON-LD Organization name, else `og:site_name`, else the part of the page titles that repeats across pages), sanitized and capped at 120 characters, as the person who started the run when they have `project.edit` on the client (`renameFromSite`, audit `client.rename` with `auto: true`). Only the name changes (the slug stays); a failure never fails the import.
- **Color roles.** When a website import proposes the site's colors, it also proposes the brand color (`color.semantic.brand-primary`: the best-ranked chromatic color readable with its text color and on the background, contrast 3:1) and the accent (the next chromatic color), as aliases of those palette colors, only for roles that still hold the starting value and have no pending proposal. They are ordinary proposals: the gate, the hand-edit rule and provenance apply, and the automatic apply takes them after the colors they name (an alias to a color that did not make it stays pending). Text and background roles are never remapped.
- **Stored texts stay English.** The changelog and note of a version an automatic import publishes or undoes ("Automatic import from …", "Undo of automatic import v2") are written in English (activity log, exports) from the `brand.import.version.*` messages and shown in the reader's language on the Versions page, like the import's page locators. A profile link that is not a profile of the chosen network is kept as a link with status partly read and the reason "Saved as a link, not read"; a profile already found by the import is the same source when added by hand (normalized address) and is read again instead of duplicated. Pictures without an alt get the title of the page they were found on (else the words of their file name) and their class.

## Consequences

- A website or profile added by a person with the right permissions changes the published Brand Identity at once. The protection is the gate, the rule that people's edits win, the activity log (`brand.proposal.auto_accept`, `brand.version.publish` with `auto: true`, the run id) and one-click undo.
- The review queue is no longer a required step. It stays for documents and for what is uncertain, and the manual submit and approve flow is unchanged.
- The `CLAUDE.md` line becomes: "AI agents propose and do not approve: `can()` in `packages/core` enforces this server-side. An import run acts on behalf of the person who started it (ADR 0022)."
- Upgrading needs migration `0033_brand_visual` (asset source `site`, `brand_sources.visual`) and changes behavior: website and social imports publish automatically. The next free migration number is 0034.
- Every automatic import costs one AI call for the interpretation (positioning, audience, voice); everything else is deterministic.

## Known limitations

- Third-party text on the client's own site (reviews, comments, testimonials) can pass the quote gate: the quote is on the page, but the words are not the brand's.
- Undo restores the version before the import, so a person's edits that were swept into the automatically published draft are dropped with it (they stay in the version history).
- Palettes that exist only after JavaScript runs, or only in `oklch()` colors, are not captured.
- Only the brand and accent color roles follow the imported colors, and only from their starting value; text, background and surface keep the neutral defaults, and only the display/body font tokens follow the imported fonts (also only from their starting value).
- A client name equal to the address guess is taken for a guess: a person who typed exactly that name in "New client" (and never saved the details again) sees it replaced by the site's name.

## Not covered

- Palettes in images.
- Social profiles blocked by `robots.txt` or behind a login wall; profile pages whose markup the extractor does not recognize.
- Vision-model palette extraction, dark-mode variants, border radius and spacing tokens, products detection and feeding the image library to image generation.
- A page that lies: the gate checks that a quote and a color are on the site, not that the site is right about itself.
