# 0014 · Sign-in and web hardening

- Status: accepted
- Date: 2026-10-08

## Context

An audit of the sign-in path and the web surface found: unlimited password guessing on `/api/auth/sign-in`, an open redirect through the login `next` parameter, an unguarded `/setup` on a fresh instance, no baseline response headers, stored SVGs that could run script when opened as a top-level document, and an AI policy that trusted the request when the ledger could not say what the Admin approved. Forgecy is an internal tool normally run on one machine, so each fix is sized for that, not for a public service.

## Decision

- **Password policy.** `PASSWORD_MIN = 1` and `PASSWORD_MAX = 128` (`apps/web/lib/password.ts`, also passed to Better Auth as `minPasswordLength`/`maxPasswordLength`). The missing minimum is intentional: the maintainer removed it in commit 2eecbfa for a single-machine internal tool and that decision stands. The compensating controls are the per-username throttle and Better Auth's per-IP limit. The maximum is counted in UTF-16 units (`password.length`) to match Better Auth and the HTML `maxLength`, so the form and the API cannot disagree. No blocklist and no composition rules.
- **Per-username sign-in throttle** (`apps/web/lib/login-throttle.ts`, Redis, key prefix `forgecy:login:`). The key is the typed identifier, normalized, whether or not the user exists, so the response gives no enumeration signal and one name never locks another. A ticket is taken in the Better Auth `before` hook, before the password is verified, so concurrent requests cannot race past the check. Five free attempts; the fifth sets a lock, and a `SET NX` decides a single winner for each lock period, who gets one attempt (then the next lock is longer): 30, 60, 120, 240, 480, then 900 s. The counter window is 3600 s (it must stay above the longest lock, otherwise waiting at the cap would buy a fresh budget). Locked requests get 429 with `Retry-After`. A non-401 error (malformed body, deactivated account after a correct password) refunds its ticket; success clears the counter. If Redis errors, the throttle fails open.
- **Change password** (settings). The server action has no throttle of its own, and its server-side call bypasses Better Auth's limiter. The HTTP route `/api/auth/change-password` is protected only by Better Auth's per-IP limit, so someone holding a stolen session cookie can still guess the current password slowly. Other sessions are revoked on success. The form is hidden for accounts without a password (`hasPassword`), and `CREDENTIAL_ACCOUNT_NOT_FOUND` maps to a plain message.
- **`FORGECY_SETUP_TOKEN`.** Optional, at least 16 characters when set. When set, `/setup` asks for it and `createFirstAdmin` checks it server-side before anything else, comparing SHA-256 digests with `timingSafeEqual`. The token never reaches the client (the page passes only a boolean). Wrong guesses go through one global setup-token throttle with the same schedule as sign-in. Unset keeps today's behavior.
- **Login `next`.** `safeNext` (`apps/web/lib/safe-next.ts`) resolves the value like a browser against a dummy origin and returns `/` for anything that leaves the origin, including `/\evil.com`, a literal tab, and dot-segment tricks that normalize to `//host`.
- **Static security headers.** `next.config.ts` sends `Content-Security-Policy: frame-ancestors 'self'; base-uri 'self'; form-action 'self'; object-src 'none'`, `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and a `Permissions-Policy` that disables camera, microphone, geolocation, payment and usb. There is deliberately no `script-src`: a nonce CSP forces every page to render dynamically and needs the proxy, so it is its own future change. Until then XSS from stored data is limited only by React escaping and the SVG sandbox. `/render/*` and `/api/files/*` are excluded because they set their own CSP (the editor frames `/render`) and a second policy would intersect with theirs. `Strict-Transport-Security` is added only when `FORGECY_BASE_URL` starts with `https://` at build time.
- **SVG downloads.** `fileResponseHeaders` (`packages/files`) always sends `nosniff`, and for `image/svg+xml` also `default-src 'none'; style-src 'unsafe-inline'; sandbox`, so an SVG opened through its signed URL is an inert image with no scripts and an opaque origin.
- **Single-tenant trust boundary.** Every active human can read every client, job and file listing by id; `can()` gates by role and action, never by client, and a `clientId` never widens what an actor may do. Core tests pin this contract. Per-client access (freelancers, client logins) is deferred: it needs a grants or members table with a generated migration, a resolver passed into `can()` and a filter in every service query, which is a milestone of its own. The SSE endpoint `/api/jobs/:id/events` already checks the job kind's permission for admin-only kinds.
- **AI gateway fails closed.** For an `external_restricted` client, a request without `clientId`, or a ledger without `approvedProviders` or `sendableAssets`, approves no cloud provider and keeps files on the local model. A request can only narrow what the Admin approved, never widen it.

## Consequences

- A known username can be kept locked by anyone who sends one bad attempt per lock period (a deliberate availability-for-safety trade). Recovery: delete the `forgecy:login:*` keys in Redis (`redis-cli --scan --pattern "forgecy:login:*"` piped to `del`). The setup-token throttle is global, so it can likewise delay the legitimate first-run admin up to 15 minutes. In a burst, refused requests that raced the TTL check inflate the counter, so an attacker's own burst escalates the next lock.
- With Redis down the throttles are off and only Better Auth's per-IP limit and the 16-character setup token remain.
- A one-character password is accepted. This is the maintainer's choice; revisit it if an install is ever exposed beyond the local network.
- Better Auth's per-IP limiter shares one bucket when no trusted client IP resolves (direct `:3000` without a proxy), so any visitor can exhaust the sign-in budget for everyone. The per-username lock does not depend on IP. Trusted-proxy configuration needs its own ticket.
- HSTS from `next.config.ts` only works when `FORGECY_BASE_URL` is https at build time, which is not the case in the Docker image. HSTS is therefore emitted by Caddy; that belongs to the Caddy hardening task (Part F), not to this change.
- There is still no Admin "set password" action and no email reset: a forgotten password is recovered at database level.
- `FORGECY_SETUP_TOKEN` is optional, so an unconfigured, network-exposed fresh instance can still be claimed by the first visitor. Making it mandatory when the auth mode is not local is a one-line env refinement if wanted.
